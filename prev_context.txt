--------------------------------------------------------------------------------
1. PROJECT PURPOSE & OVERVIEW
--------------------------------------------------------------------------------
Eventify is a modular, high-performance desktop application for campus and
organizational event planning, participant management, scheduling, and gamified
engagement. It is built to satisfy all requirements for the CSE-2200 course,
demonstrating mastery over:
  - Object-Oriented Programming (OOP) design and clean code architecture.
  - Modern Java 21 features (Records, Pattern Matching, Switch Expressions, Text Blocks).
  - JavaFX GUI with FXML declarative layouts and custom CSS styling.
  - Multi-threaded background task processing (preventing UI freeze).
  - SQLite embedded relational database with ACID transactions and foreign keys.
  - Secure credential storage (PBKDF2 with SHA-256 and cryptographic salting).
  - External REST API integration (Nager.Date Public Holiday API) & JSON processing (Gson).
  - Comprehensive unit and integration testing.

4. DATABASE ARCHITECTURE & SCHEMA
--------------------------------------------------------------------------------
Database file path:
  Windows: %USERPROFILE%\.eventify\eventify.db (e.g. C:\Users\ASUS\.eventify\eventify.db)

Enforced Pragmas:
  PRAGMA foreign_keys = ON;
  PRAGMA busy_timeout = 5000;

Tables:
  1. users:
     - id (INTEGER PRIMARY KEY AUTOINCREMENT)
     - name (TEXT NOT NULL)
     - email (TEXT NOT NULL COLLATE NOCASE UNIQUE)
     - password_hash (TEXT NOT NULL)
     - role (TEXT NOT NULL CHECK(role IN ('ADMIN', 'PARTICIPANT')))

  2. events:
     - id (INTEGER PRIMARY KEY AUTOINCREMENT)
     - title (TEXT NOT NULL)
     - description (TEXT NOT NULL DEFAULT '')
     - venue (TEXT NOT NULL)
     - event_date (TEXT NOT NULL, YYYY-MM-DD)
     - event_time (TEXT NOT NULL, HH:mm)
     - capacity (INTEGER NOT NULL CHECK(capacity > 0))

  3. registrations:
     - event_id (INTEGER NOT NULL REFERENCES events(id) ON DELETE CASCADE)
     - user_id (INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE)
     - attended (INTEGER NOT NULL DEFAULT 0 CHECK(attended IN (0, 1)))
     - PRIMARY KEY (event_id, user_id)

  4. schedule:
     - id (INTEGER PRIMARY KEY AUTOINCREMENT)
     - event_id (INTEGER NOT NULL REFERENCES events(id) ON DELETE CASCADE)
     - title (TEXT NOT NULL)
     - start_time (TEXT NOT NULL, HH:mm)
     - end_time (TEXT NOT NULL, HH:mm)
     - speaker (TEXT NOT NULL DEFAULT '')

  5. tasks:
     - id (INTEGER PRIMARY KEY AUTOINCREMENT)
     - event_id (INTEGER NOT NULL REFERENCES events(id) ON DELETE CASCADE)
     - title (TEXT NOT NULL)
     - assignee_id (INTEGER NOT NULL)
     - due_date (TEXT NOT NULL, YYYY-MM-DD)
     - points (INTEGER NOT NULL CHECK(points > 0))
     - done (INTEGER NOT NULL DEFAULT 0 CHECK(done IN (0, 1)))
     - FOREIGN KEY(event_id, assignee_id) REFERENCES registrations(event_id, user_id) ON DELETE CASCADE

Business Logic & Integrity Rules:
  - Leaderboard Score Formula:
      Total Score = (attended == 1 ? 10 : 0) + SUM(tasks where done == 1)
      Rank calculation: Dense ranking with tied scores sharing the same rank.
  - Schedule Overlap:
      No two sessions within the same event may have overlapping [start_time, end_time).
      Session start_time cannot be earlier than event event_time.
  - Registration Integrity:
      Cannot register for past events.
      Capacity limit cannot be exceeded.
      Deleting an event cascades and cleanly removes registrations, schedule, and tasks.

6. SUMMARY OF RECENT BUGS FIXED & STABILIZATION
--------------------------------------------------------------------------------
1. Sequential Table Index (# Column):
   - Issue: Deleting rows left gaps in IDs (e.g., ID 1, 3, 4), confusing the user.
   - Solution: Added `indexColumn()` in MainController.java using dynamic cell factory
     `setText(String.valueOf(getIndex() + 1))`. The `#` column now continuously reflects
     1, 2, 3... dynamically even when items are filtered or deleted.

2. Modal Dialog Clarity & Hints:
   - Issue: Dialogs lacked clarity on formats (date, time, capacity).
   - Solution: Enhanced `Forms.java` with explicit labels, placeholders ("HH:mm, e.g. 09:30",
     "YYYY-MM-DD", "e.g. Main Auditorium"), and explicit column width constraints.

3. Automated Test Participant Seeding:
   - Issue: Seeding previously checked `COUNT(*) == 0` for participants globally, skipping
     test accounts if any user had already signed up. Also, new events had 0 registrations.
   - Solution: Updated `Database.initialize()` to use `INSERT OR IGNORE` for Alice, Bob, and
     Charlie unconditionally. Added dynamic auto-seed in `Database.snapshot()`: if the
     active event has 0 registrations, Alice & Bob are immediately linked with sample tasks
     so the Admin can test attendance, task completion, and leaderboard immediately.
